# T-604: Governed ISO 20022 bank-action exchange

**Goal.** Demonstrate one authorized stuck-payments operation crossing a mock ISO 20022-speaking bank middleware, then verify the bank's response before Calvino reports an outcome. MCP is the governed tool interface; ISO 20022 is the bank-facing financial message, **not** a substitute name for Calvino's allow/ask/block verdict.

**Inputs.** the full cleaned-table adapter and existing conformance boundary (T-206), the Gate's decision and exact typed confirmation, a selected ISO 20022 message version and implementation profile, synthetic core-middleware responses and an audit correlation reference. T-406 separately proves adapter swap; neither experiment blocks the other. The profile's required fields are checked against actual available source fields before a message type is selected.

**Outputs.** a deterministic mapper for one selected cancellation **or** investigation exchange; official-schema and chosen-profile validation; semantic checks binding owner, original reference, amount, currency, action, idempotency and authorization to verified source evidence; an outbound message correlated with a separate Calvino verdict, a simulated bank acknowledgement/rejection and a verified read-back. Unsupported mappings and uncertain responses fail closed. No LLM writes XML or turns a Calvino verdict into a payment-status code.

**Open parameters.** Choose and pin the actual message family, version and bank profile in the detailed spec; confirm required elements and availability from the synthetic source before implementation. A cancellation and an investigation are not assumed to share one message shape.

**Done when.** one successful and multiple refused/rejected synthetic cases prove the entire Gate → message → mock middleware → response/read-back → customer-claim boundary; malformed, schema-valid-but-semantically-wrong, cross-customer, duplicate, mismatched-reference and uncertain-response cases are blocked and logged. Report schema-pass and **semantic false-accept** counts with denominators, not just XML validity. Claim conformance only to the selected version/profile in the mock exchange, never general ISO compliance or a live core connection.

**First step:** turn this card into a full specification in `docs/specs/` (next free TSD number), with interfaces, tests and done criteria, and get the maintainer's approval before implementing.
