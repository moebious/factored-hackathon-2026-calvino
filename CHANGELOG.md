- The judge sends an explicit completion budget, sized from the rubric (`OpenAiJudge.token_budget`): every reachable model reasons before it answers (one word cost 109-116 output tokens; a 24-token judge call returned finish_reason "length" with nothing but thinking), so an unset budget meant an unbounded answer and a small one truncates before any verdict is emitted.

NFR-1 keeps customer text for decisions with a self-hosted model, so amounts and merchants - which already travel as structured evidence - become placeholders, matched by value rather than spelling, and other customers' markers are redacted. Without this the `question-fully-answered` criterion failed every reply for want of the question, which measures the harness rather than the judge.

### Changed
- The demo endpoints are open (decision 38): the shared `CALVINO_DEMO_PASSCODE` gate and its `x-calvino-passcode` header are removed from the API, the config, the frontend and the smoke check. A judge clicking the link must never face a login wall, and the rate limit already covers casual abuse; the per-client rate limit (first `X-Forwarded-For` entry, `CALVINO_DEMO_RATE_LIMIT`) and the fail-closed `CALVINO_CONFIRMATION_KEY` for hub writes remain the guards. The hub is now wired at startup on the confirmation key alone, so opening the endpoints does not disable it.
- Fine-tuning becomes the roadmap's critical path: the measured `needs_human` overlap behind 13 of 50 unnecessary escalations cannot be fixed by a threshold or by calibration, so T-106 → T-202 (first slice `needs_human` and `workflow_area`) → T-201 → a candidate replay are ordered gates with a stop rule; the roadmap prerequisites note that the keyed run used a test judge.
- Status bookkeeping in line with main: task and spec statuses (TSD-012, TSD-013, TSD-015 implemented; T-103, T-303, T-304 in progress), decision 33 (per-language thresholds become `policy/v3.yaml`), and the handoff's current state and next actions, led by the missing public link, Portuguese coverage and the evaluation re-run.

- Evaluation park semantics (TSD-013 amendment): an `operator_queue` park the resume script cannot answer ends the turn as a scored `HUMAN_QUEUE` outcome instead of a harness `error` — measured on the first tier0 run, where live laya 0.3.24 over-escalated 13 of 50 routine Spanish cases (needs_human 0.67–0.89, overlapping explicit-human requests at 0.87–0.98, so no policy threshold separates them), and counting that system behaviour as harness errors kept it out of every rate. Over-escalation now scores as a mismatch and shows up in the escalation-quality metric; `error` remains for raises, unknown park kinds and `approve_action` parks the script cannot answer.
- The Space image pins `laya==0.3.24` exactly instead of the floating `>=0.3.23,<0.4` range: 0.3.24 is the version TSD-005 wraps and the calibration was fit against, and laya 0.3.26's classifier calls `torch.is_autocast_enabled(device)` (needs torch ≥ 2.4), which broke every classify call on torch 2.2.2 `[measured]` on the first live local run. Bumping laya now means re-running the calibration and the deployment smoke check.
- Policy v2 (`policy/v2.yaml`, decision 30): the route's `min_clear_enough` lowered from 0.50 to 0.30 on the first live measurement of laya 0.3.24's scores on the demo scenarios `[measured]` — terse routine commands score clear_enough 0.20–0.35, so under v1 no wording of a routine action request reached the agent path. The Gate's own 0.70 clarity check is unchanged, so an unclear write still parks for confirmation; v1 stays on disk for replay per the immutability rule, and the default loader now reads v2.
- Demo scenario messages tuned to laya 0.3.24's measured scores (decision 30): UC-2 "Buenas, tengo una duda con un pago de mi cuenta" (needs_human 0.677 → the clarify picker), UC-3 "¿Puedes ayudarme con mi tarea de matemáticas?" (out-of-scope 0.815 → the honest refusal) and UC-5 "Reintentar transferencia E-US-001" (needs_human 0.176, clear_enough 0.338 → RT-ACT under policy v2, then parked at GATE-UNCLEAR for the customer's confirmation). Synced across the frontend buttons, the live smoke check and the seeded AC-2/AC-3 fixtures; the fixtures keep their scripted probabilities, so the acceptance criteria themselves are unchanged.
- The agent-role LLM provider is Hetzner's Inference API and the judge stays on a second provider (decision 28, refining 20); DESIGN, ROADMAP, PLAN and the backlog name the `CALVINO_LLM_*` and `CALVINO_JUDGE_*` variables, and using a chat API as the System One classifier is recorded as rejected.

### Fixed
- `calvino.api` resolves its public names on first use instead of importing them eagerly, which removes an import cycle: `calvino.hub.graph` imports `calvino.api.decide`, whose import ran `calvino.api.__init__`, which imported `calvino.api.app`, which imported `calvino.api.hub`, which imported `calvino.hub` while `calvino.hub.__init__` was still running. `pytest tests/calvino/hub` failed on its own with `ImportError: cannot import name 'DEMO_PERSONAS'` while the full suite passed, so CI never saw it; the hub tests now run in any order.

- The deployment smoke check accepts parked turns: an operator-queue park legitimately carries an empty reply and no card, but `_turn_evidence` demanded a card or reply from every scenario kind before the kind branches ran, which failed a healthy hub on the first live local run. The trace requirement stays for all kinds; the card-or-reply rule now applies to the reply kind only, and the deployment test stubs mirror the real parked shape.
